# Полный состав сводок и видимый поток подагентов

Владелец сообщил, что под цитату продолжает попадать полезная работа агентов, и показал нативные «Ran 23 commands» / «Ran 16 tools» рядом со сводками Minus. Продолжается уже порученное исправление и установка обновления. Словарь передан другому треду: `quotes.ts` в эту редакцию не входит.

## Причина и изменение

Поиск по штатному conversation outline нашёл точную фразу со скриншота за пределами тредов Minus. Настоящие API и DOM подтвердили обе причины: одна нативная сводка объединяет несколько групп API, разделённых reasoning; другая объединяет инструменты и подагентов. Раньше счётчик смотрел только на первую группу, а защита потока оставляла всю смешанную сводку необработанной.

Состав нативной сводки теперь восстанавливается по её собственному количеству вызовов в той же API-последовательности. Следующая смонтированная нативная строка задаёт жёсткую границу: устаревший API не позволяет брать её первый вызов для предыдущей сводки. Неполный или противоречивый снимок оставляет нативное количество и неизвестное время. Для подтверждённых вызовов складываются их собственные завершённые интервалы, включая параллельные. В настоящей сводке со скриншота это 16 вызовов и 74411 ms, отображаемые как `16 tools · 1m 14s`.

Смешанная оболочка открывается штатной кнопкой BB; её общий заголовок убирается, прямые инструменты группируются, работа подагентов остаётся снаружи. Нативная подпись о подагенте или workflow имеет приоритет над устаревшей классификацией API. Дочерние timelines подагентов и workflows не обрабатываются. Доказанно видимый ранее поток защищён и при перепаковке в новую закрытую summary, в том числе после ошибки API; уже подтверждённая stream-summary запоминается до cleanup. Ручное закрытие сохраняется; cleanup возвращает автоматически открытые оболочки и обратимый фокус. Сохраняются ранее исправленные границы measure row и внешних контейнеров.

## Проверка редакции

62 теста, TypeScript и сборка прошли. Независимый reviewer снял замечания о пересечении соседних сводок, приоритете нативного признака подагента и перепаковке известного стрима; пять независимых адресных проб прошли на точных исходниках. Настоящий исходный сценарий прошёл в одноразовом клиенте на 1280 и 390, с текущими JS/CSS кандидата; API-содержимое не перехватывалось. Время 74411 ms независимо вычислено по всем 16 timestamps. Результаты и точные хеши сохраняются в [комплекте доказательств](verification/2026-10-30-summary-membership/). Приватные API, DOM и скриншот владельца остаются только в thread storage; публикуются санитизированные примеры и метаданные проверки без текстов чужих тредов.

Проверяются: полные 16 вызовов через reasoning; summary с первым reasoning; неполное API-окно; смешанная сводка с инструментами и delegation; ручное закрытие и cleanup; оба случая пересечения соседних summary при устаревшем API; нативная подпись подагента при устаревшей API-классификации. Настоящий frontend проверяется в одноразовом isolated headless Chromium на 1280 и 390: сообщения и delegation видны при Enter/Space по метрикам, служебные tools скрываются. Визуальные примеры снимаются штатным local-ui-capture, в обеих темах и состояниях.

`bb-plugin-workflow` / `bb-plugin-authoring`: manifest, backend, зависимости и pin SDK не меняются; используются существующие публичные timeline/subscription API и нативная кнопка. Проверка `bb plugin types --check` сообщает прежнее различие pin 0.6.79 и host 0.6.94; это не считается PASS и не служит разрешением менять SDK. TypeScript и сборка проверяются отдельно, браузер использует SDK и frontend работающего BB.
