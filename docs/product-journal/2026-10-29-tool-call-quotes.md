# Цитаты в свёрнутых вызовах Minus

## Задача и решение

Цель изменения (2026-10-28): добавить в Minus случайную локальную русскую цитату к свёрнутым вызовам инструментов и подготовить отдельный PR к проверке. Свёрнутая группа показывает короткий курсивный текст, автора и ссылку на источник; кнопка сохраняет раскрытие/сворачивание и доступное имя со счётчиком. Источники загружаются из локального кода, сетевого запроса при показе нет.

Изменение оформляется отдельно от PR #1 с регрессионными тестами. Настройка `collapseToolCalls`, группировка, виртуализация, SDK, серверная часть, иконка и другие переключатели не меняются.

## Реализация

- `quotes.ts` содержит 200 русских переводов и восемь источников открытых англоязычных текстов Project Gutenberg; запись хранит исходный фрагмент и локатор строки.
- `group-tools.ts` показывает цитату в существующей компактной строке, добавляет отдельную ссылку на источник и оставляет количество и действие в доступном имени кнопки.
- `group-tools.test.mjs` проверяет поведение DOM, виртуализацию, ссылки и структуру подборки; `jsdom` добавлен как dev dependency. DOM-классификатор отделяет смонтированные системные строки прерывания, а API-run index разделяет группы, если такую границу заменил virtualizer spacer.
- Обновлены описание настройки, README, обзор плагина и инструкция Minus.

## Проверки и ограничения

- Сверка источников: 200/200 исходных фрагментов сопоставлены с заявленными строками; SHA-256 всех восьми файлов совпадает с манифестом проверки.
- Сохранённый JUnit содержит 17 пройденных тестов и 0 ошибок: 14 DOM-сценариев и 3 проверки подборки цитат. Включены сценарии для 1, 2 и 3 смонтированных строк, отдельная виртуализированная строка, смонтированное и виртуализированное ручное прерывание, задержка API-ответа при уже раскрытой группе, пропущенный API ID и замена первой строки virtualizer'ом.
- `tsc --noEmit --pretty false`, `bb plugin build .` и `git diff --check` прошли после исправлений. Для TypeScript добавлены dev-зависимости по peer-диапазонам SDK; пин SDK остался 0.6.79.
- Независимый редакторский проход охватил 200 переводов и выявил восемь смысловых расхождений в ранее не перепроверенных строках; формулировки исправлены и закреплены тестом. Точечная независимая повторная проверка восьми исправлений не выявила новых замечаний.
- Независимое read-only ревью точного commit `e080b436d9d49c5f147b12139db2be62577013e7` не нашло новых дефектов поведения группировки, доступности, источников или зависимостей; SDK pin остался 0.6.79, новые пакеты находятся только в `devDependencies`.
- Повторная проверка кода после возобновления: независимый ревьюер не нашёл новых замечаний на `9dfaec3a713ab3f795c6749dd32c35a3c20f8bb7`; от `e080b43` и до текущего кандидата менялся только журнал, функциональные исходники и тесты совпадали.
- Дизайн-проход для текущего ряда в режиме Operate: Impeccable распознал узкое расширение существующего интерфейса без `PRODUCT.md`/`DESIGN.md`; просмотренные DOM-классы сохраняют семантические цвета BB, `text-sm`, курсив и обрезание цитаты, а источник оформлен отдельной ссылкой с `text-primary` и `ring-ring`. Кнопка сохраняет нативную семантику, явный стиль `focus-visible`, доступный счётчик и связь с цитатой через ARIA. Новая визуальная основа не вводилась; клавиатурный сценарий и отрисованный focus state live не проверены.
- Встроенный Impeccable detector просканировал только `.ts` regex-правилами и указал, что этот результат неполный. Установленная команда `polish` отсутствует.
- Визуальный рендер не проверен: установленный Minus остаётся на upstream `v0.2.1` (`bffa4ad`), а `local-ui-capture` не находит Playwright в `node_modules` этого checkout. Общий host не менялся.
- Проектные инструкции не найдены в checkout; попытка чтения `vadikhq/IDE/projects/bb-plugin-minus.md` завершилась 404. GitHub Actions workflow отсутствуют и не запускались.

## Регрессионная правка для ручной остановки — 2026-10-29

- На локальной редакции поверх опубликованного `50b406f3266d48af5784076dcbe5facc849b1185` подтверждено, что системное прерывание представлено в SDK как `kind: "system"`, `operationKind: "thread-interrupted"`; его DOM id относится к `op:thread-interrupted`. DOM fallback мог включить смонтированную строку в группу; review также нашло, что spacer на месте виртуализированной остановки позволял объединить вызовы по обе стороны, потому что API-счётчик суммировал несколько run.
- `group-tools.ts` исключает `op:thread-interrupted` из DOM-классификатора и разделяет группу, если API показывает разные run. Spacer на такой границе остаётся снаружи групп; неизвестный API ID получает отдельную fallback-группу, а уже раскрытая fallback-группа сохраняет открытость после разделения. `group-tools.test.mjs` проверяет видимую строку `Stopped manually`, счётчик одной работы по обе стороны, виртуализированный interruption/spacer и независимое раскрытие соседних групп.
- Для этой редакции: 17/17 тестов прошли (14 DOM-сценариев и 3 проверки подборки цитат), TypeScript и `bb plugin build .` завершились успешно, `git diff --check` прошёл. JUnit сохранён в артефактах текущего треда.
- Проверка Impeccable выявила, что у проекта нет `PRODUCT.md`/`DESIGN.md`, а исходная компактная строка — действующая визуальная основа. Здесь не менялись шаблон, стили, цитаты или ссылка: ручное прерывание остаётся отдельной нативной строкой, не скрываемой сворачиванием. Live-снимок и установленный runtime для этой редакции не проверялись; общий host не затрагивался.
- Независимые read-only проходы выявили границу виртуализированного spacer, сохранение раскрытия fallback-группы при замене смонтированной строки, а также unknown ID внутри и между API-run. Все сценарии исправлены и закреплены тестами; финальное ревью текущей редакции ещё выполняется. Код локальный и не закоммичен, отдельного PR пока нет.

### Повторная проверка раскрытия после прокрутки — 2026-10-29

- Независимое ревью нашло, что при переходе видимых групп A+B → B+C открытая API-группа B повторно переносила состояние раскрытия на новую группу C. Это не было состоянием старого DOM-fallback.
- В `group-tools.ts` перенос при разделении теперь читает только раскрытие по fallback-ключу. API-группа сохраняет своё состояние, а новая группа остаётся закрытой. `group-tools.test.mjs` закрепляет смену виртуализированного окна и проверяет `aria-expanded` и видимость B/C; уже существующий сценарий «Stopped manually» подтверждает две группы по одному вызову и видимую строку остановки.
- Проверка SDK: тип timeline задаёт системное событие `operationKind: "thread-interrupted"` при `kind: "system"` (`node_modules/@get-bb/plugin-sdk/bundled-types/bb-plugin-sdk.d.ts:12011`). Индекс групп учитывает только строки `kind: "work"` и reasoning; DOM-фильтр исключает `op:thread-interrupted`.
- Текущая локальная редакция: JUnit — 18 тестов, 0 failures/errors/skipped; `npx tsc --noEmit --pretty false`, `bb plugin build .` и `git diff --check` завершились успешно. JUnit: `$BB_THREAD_STORAGE/minus-tests.xml`.
- Источники этой редакции до commit: SHA-256 `group-tools.ts` — `ecd25081472be6f73a35dcf027fa879dc910c84b781ff7a06fd9c92d2895fd62`; `group-tools.test.mjs` — `4047983dfc95ff7d2d0248ed6ec5d227564eb89a1d90150b760f2d374bf794d2`.
- Operate/harden-проход Impeccable и Frontend Design: оставлена текущая компактная нативная строка и её toggle; состояние каждой API-группы теперь независимо переживает смену окна. Новая поверхность, стиль и движение не добавлялись. JS DOM-тесты проверяют disclosure state и скрытие строк; live BB render не запускался, общий host не менялся.
- Проектный `AGENTS.md` в checkout отсутствует; `vadikhq/IDE/projects/bb-plugin-minus.md` при read-only запросе GitHub вернул 404. Workflow-файлов в base нет, GitHub Actions не запускались.
- Реализация и регрессионные тесты этой редакции зафиксированы коммитом `810d77528141a84228bb674b7b4109361a5cdbc5` и опубликованы в feature-ветке форка; local и remote head совпали. PR с цитатами ещё не открыт.

## Стадия и откат

На момент возобновления local `HEAD` и `origin/bb/minus-tool-call-quotes` совпадали на `9dfaec3a713ab3f795c6749dd32c35a3c20f8bb7`; feature-ветка уже опубликована в форке `vadikhq/bb-plugin-minus`, отдельный PR с цитатами ещё не создан. PR #1 остаётся открытым на отдельной ветке и не менялся. Его DOM-тесты проверяют `Called N tools` в видимом содержимом кнопки; цитатная редакция заменяет эту подпись цитатой, сохраняя счётчик в `aria-label`. Если PR #1 будет интегрирован после цитат, его ожидание видимого текста потребуется согласовать с новым сценарием; этот PR остаётся вне области текущей ветки.

Точный визуальный рендер кандидата не получен: установленный Minus остаётся на upstream `v0.2.1` (`bffa4ad`), а `local-ui-capture` не находит Playwright в `node_modules` этого checkout. По правилам capture helper ничего не устанавливал; `bb plugin dev` не запускался, потому что подключён к общему host и перезагружает установленный плагин. GitHub Actions workflow в fork и upstream отсутствуют. Перед созданием PR нужно показать владельцу полный заголовок и текст; merge требует отдельного подтверждения URL, SHA, base и метода.

Если поведение нужно отменить после слияния, сделать revert feature-коммита. До слияния не удалять ветку или PR без отдельного согласования.
